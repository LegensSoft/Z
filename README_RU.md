# SimpleDLC FileBot — aiogram 3 и переменные окружения

Бот полностью использует aiogram 3.31.0: Bot, Dispatcher, Router, фильтры, middleware, FSM и long polling. Токен и ID владельца/основных чатов читаются из переменных окружения. База SQLite, выдача файлов, черновики, публикации, спонсоры и реклама сохранены.

## Запуск

1. Останови старый экземпляр бота и распакуй архив целиком в отдельную папку.
2. Установи зависимости и запусти бота:

```sh
python -m pip install -r requirements.txt
python main.py
```

В этот архив включены `.env` с настройками из исходного архива и исходная `data/bot.sqlite3`. Токен и настроечные ID убраны из Python и JSON. Не публикуй `.env` и базу данных. При обновлении уже работающей копии предварительно сохрани её актуальную базу: база в этом архиве соответствует моменту загрузки исходного ZIP.

В Pydroid 3 открой `main.py` или `START_PYDROID.py` рядом с остальными файлами. Если зависимости отсутствуют, первый запуск предложит их автоматическую установку. После успешной установки запусти файл ещё раз. Поддерживается Python 3.10+; на Android установка aiohttp и pydantic-core зависит от доступности совместимых пакетов Pydroid.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `BOT_TOKEN` | Токен из BotFather |
| `TELEGRAM_BOT_TOKEN` | Альтернативное имя токена |
| `ADMIN_ID` | Один положительный Telegram ID владельца |
| `ADMIN_IDS` | Алиас `ADMIN_ID`; тоже один ID, без списка и скобок |
| `STORAGE_CHANNEL_ID` | Отрицательный ID канала/группы хранилища, `@username` или ссылка Telegram; `0` — не привязан |
| `MAIN_CHANNEL_ID` | ID основного канала, `@username` или ссылка; `0` — не привязан |
| `CHANNEL_CUSTOM_EMOJI` | Логический параметр совместимости, по умолчанию `true`; не управляет правами Telegram |
| `DOWNLOAD_COOLDOWN_SECONDS` | Пауза между выдачами: 1–60 секунд, по умолчанию 2 |

Сначала берутся значения из окружения процесса, затем из `.env` рядом с исходниками. `BOT_TOKEN` имеет приоритет над `TELEGRAM_BOT_TOKEN` в одном источнике. Алиас из окружения процесса имеет приоритет над основным именем в файле. Аналогично работают `ADMIN_ID` и `ADMIN_IDS`.

Для нового бота скопируй `.env.example` в `.env` и заполни его. Существующий `.env` в этом архиве уже содержит перенесённые настройки. Значения не печатаются при запуске. Файл `.env` добавлен в `.gitignore`.

Запуск только через окружение также поддерживается, `.env` не обязателен:

```sh
export BOT_TOKEN='ТОКЕН_ИЗ_BOTFATHER'
export ADMIN_ID='ТВОЙ_TELEGRAM_ID'
export STORAGE_CHANNEL_ID='ОТРИЦАТЕЛЬНЫЙ_ID_ХРАНИЛИЩА'
export MAIN_CHANNEL_ID='ОТРИЦАТЕЛЬНЫЙ_ID_КАНАЛА'
python main.py
```

Схема чтения токена в `settings.py` использует:

```python
import os

token = os.getenv("BOT_TOKEN") or os.getenv("TELEGRAM_BOT_TOKEN")
```

Если в окружении токена нет, используется `.env`; после проверки конфигурации `runtime.py` создаёт `Bot(token=cfg.bot_token)`. Проверка ID владельца остаётся такой же, как в исходнике: ровно один владелец. `config.json` и `preset.json` больше не читаются, запросов токена через `input()` нет.

## Каналы и ID

Открой `/admin` → «Каналы». Основной канал и хранилище должны быть разными. Хранилище может быть каналом, обычной группой или супергруппой; основной чат публикаций — каналом.

Если ID взят из `.env`, изменение через админку атомарно сохраняется обратно в `.env` и применяется без перезапуска. Остальные строки и комментарии файла сохраняются. Если ID задан в окружении процесса, для смены чата измени переменную окружения и перезапусти бота: админка сообщит об этом, вместо сохранения значения, которое окружение затем перекроет.

Для получения ID запусти `python setup_ids.py` вместо основного бота. Помощнику достаточно `BOT_TOKEN` или `TELEGRAM_BOT_TOKEN`; `ADMIN_ID` не нужен. Напиши боту в личные сообщения, перешли пост канала или опубликуй сообщение в канале. После получения ID останови помощник и запусти `main.py`. В группе владелец может выполнить `/id` или `/storage`.

## Возможности

- `/admin`: загрузка файлов, посты, черновики, заготовки выдачи, реклама, спонсоры, каналы и диагностика.
- `/start`: начало работы; `/start <ID>` — выдача файла; `/start p_<ID>` — предпросмотр поста.
- `/diag`: проверка доступности чатов и прав бота.
- `/resume` и `/cancel`: продолжение или отмена ввода.
- `/mysub`: управление проверкой подписок для владельца.
- `/id`: ID пользователя или чата.

SQLite хранит рабочие данные: файлы Telegram, посты, ID сообщений и подписчиков, спонсоров, рекламу, историю выдач и состояние ввода. Эти ID появляются во время работы бота и остаются в базе; конфигурационные ID владельца, хранилища и основного канала берутся из окружения или `.env`.

Логи создаются заново в `data/bot.log`, токены в них маскируются. Одна копия бота должна работать с одним токеном. Работа с реальным Telegram требует действующего токена, доступа в интернет и необходимых прав в выбранных чатах.

## Проверки

```sh
python -m unittest discover -s tests -v
python checks/offline_checks.py
```

Тесты используют aiogram и подменяют ответы Telegram, не запускают реальный polling и не читают токен из рабочего `.env`. Проверки конфигурации находятся в `tests/test_environment.py`. Для приёмки в Telegram после запуска открой `/admin`, выполни `/diag`, загрузи тестовый файл и проверь выдачу по его ID.
