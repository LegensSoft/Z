# FlyerHubs и пропуск подписок

1. Создай `.env` рядом с main.py по `.env.example`. Перенеси свои BOT_TOKEN, ADMIN_ID и ID каналов.
2. Зарегистрируй своего бота в FlyerHubs как бот обязательных подписок (тип sub) и включи его в кабинете. Его ключ укажи в FLYER_BOT_KEY. Это отдельный ключ, не токен BotFather.
3. Укажи FLYER_ENABLED=1 и перезапусти бота. В /admin → FlyerHubs → Проверить API можно проверить подключение. Бот не создаёт рекламные кампании за тебя; наличие заданий зависит от кабинета FlyerHubs.
4. Если платформа выдала отдельную ссылку на задания, можно задать FLYER_TASK_URL. Пустое значение допустимо, ссылки не выдумываются.

При входе и перед действиями пользователя проверяются и текущие спонсорские каналы, и FlyerHubs /check. Ответ skip=false требует выполнения заданий. Ошибки API и неправильный формат ответа не открывают выдачу. Администратору отправляется уведомление без ключа API.

У администратора пропуск включён по умолчанию, если он раньше явно не сохранял другую настройку. /admin → Пропуск подписок или /mysub включает/выключает пропуск только для его аккаунта. Значение хранится в SQLite. Пользователь не может получить пропуск через callback или запись предпочтения. Управление ботом доступно администратору при сбое подписок.

Если FlyerHubs не нужен, оставь FLYER_ENABLED=0: обычные подписки на спонсоров продолжают проверяться. Если FlyerHubs включён, но ключ пустой, выдача пользователям закрывается до исправления конфигурации; администратор с пропуском может войти в панель.

Запуск на телефоне: установка зависимостей через install.py, затем START_PYDROID.py или main.py. В архиве нет токена: свои настройки нужно перенести. Существующую рабочую базу не заменяй старой копией из архива.
